Ein Benutzerkonto steht für eine Person in Mardu. Es ordnet ihr Anmeldung, Berechtigungen, Nachweise, Buchungen und Zutrittsereignisse zu.

Diese Erklärung richtet sich an Personen, die Mardu nutzen oder Benutzerkonten verwalten. Die Schritte zum Anlegen und Bearbeiten stehen unter [Benutzer und Rollen](../administration/benutzer-rollen.mdx).

## Was kann ein Benutzer tun?

Welche Funktionen die Person nutzen darf, hängt von ihren zugewiesenen Rechten ab. Dazu können die Pflege des eigenen Profils, Ressourcenbuchungen, Zugangsbeantragungen oder Verwaltungsaufgaben gehören. Ein angelegtes Konto erhält nicht automatisch Zugriff auf alle Funktionen oder Ressourcen.

Dabei werden drei Fragen getrennt geprüft:

| Frage                                                              | Was dafür zählt                                                                                                |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| Darf sich die Person anmelden?                                     | Kontostatus und Anmeldebedingungen, etwa E-Mail-Bestätigung, Freigabe und Zwei-Faktor-Authentifizierung (2FA). |
| Darf sie eine Funktion im Dashboard nutzen?                        | Berechtigungen aus direkt zugewiesenen Rollen und aus den Rollen ihrer Benutzergruppen.                        |
| Darf sie eine Ressource nutzen oder einen Zutrittspunkt passieren? | Die für diesen Zugang festgelegten Bedingungen, zum Beispiel eine Freigabe oder ein gültiger Nachweis.         |

Ein aktives Konto kann deshalb trotzdem eine Anmeldebedingung noch nicht erfüllen. Ebenso bedeutet die Leseberechtigung für Geräte im Dashboard nicht, dass die Person eine Maschine nutzen darf.

## Wie entsteht ein Konto?

Es gibt mehrere Wege. Welche davon verfügbar sind, hängt von der Einrichtung des Systems ab.

| Weg                                    | Ablauf                                                                                                                                              |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Einladung durch die Administration     | Das Konto wird angelegt. Die Person setzt ihr Passwort über den Einladungslink; anschließend wird das Konto freigegeben.                            |
| Anlage mit Passwort                    | Die Administration legt ein Initialpasswort fest. Eine Passwortänderung bei der ersten Anmeldung kann vorgeschrieben werden.                        |
| Selbstregistrierung                    | Die Person registriert sich selbst, wenn dies aktiviert ist. Je nach Richtlinie ist zusätzlich eine Freigabe erforderlich.                          |
| Verzeichnissynchronisierung            | Eine eingerichtete LDAP-Anbindung übernimmt Personen aus einem externen Benutzerverzeichnis.                                                        |
| Anmeldung über einen externen Anbieter | Bei einer eingerichteten OpenID-Connect-Anbindung (OIDC) kann die erste Anmeldung ein Konto anlegen, wenn die automatische Kontoanlage erlaubt ist. |

Ein lokales Konto verwaltet Mardu selbst. Auch bei externer Anmeldung gibt es ein Konto in Mardu, dem Rollen, Buchungen und Nachweise zugeordnet sind. Der Anbieter kann bestimmte Angaben verwalten. Solche Felder sind in Mardu gekennzeichnet und schreibgeschützt; Änderungen erfolgen beim Anbieter. Die externe Anmeldung allein erteilt keine Ressourcenfreigabe.

## Welche Zuordnungen gehören zum Konto?

| Zuordnung                        | Zweck                                                                                                                                                                  |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rollen                           | Weisen Berechtigungen für Funktionen und Aktionen in Mardu zu. Eine direkte Rolle ist dem einzelnen Konto zugewiesen.                                                  |
| Benutzergruppen                  | Ordnen mehrere Personen einer Gruppe zu. Die Rollen der Gruppe gelten für alle Mitglieder.                                                                             |
| Einweisungen und Kompetenzen     | Bestätigen eine für die Person anerkannte Fähigkeit, zum Beispiel eine Maschineneinweisung. Die Anerkennung muss aktuell gültig sein, wenn die Ressource sie verlangt. |
| Badges und importierte Nachweise | Dokumentieren Leistungen oder Qualifikationen. Ein Badge oder ein importierter Nachweis ist für sich noch keine lokale Kompetenzanerkennung.                           |
| Ressourcenfreigaben              | Ordnen einer Person, einer Benutzergruppe oder einem Tag die Nutzung einer Ressource im festgelegten Zeitraum zu. Weitere Bedingungen der Ressource gelten weiterhin.  |
| Buchungen                        | Reservieren einen Zeitraum. Ob eine bestätigte Buchung auch als Nachweis für den Zugriff zählt, hängt von ihrer Zuordnung und der Zugriffsregel der Ressource ab.      |
| Tags                             | Identifizieren die Person am Zutrittspunkt, etwa über einen RFID-Tag. Die Tag-Zuweisung allein gewährt keinen Zugang.                                                  |

Die Person kann dieselbe Rolle direkt und über mehrere Gruppen erhalten. Entfernst du nur eine dieser Zuweisungen, kann die Rolle über die übrigen Zuweisungen weiterhin gelten. In der Administration zeigt **„Effektive Berechtigungen“** die gespeicherten Rechte mit ihren Quellen.

Eine Ressource kann eine Freigabe, eine Buchung, eines von beiden oder beides verlangen. Eine zusätzlich geforderte Einweisung oder Aufsicht muss ebenfalls erfüllt sein. So kann eine Person die Buchungsfunktion verwenden dürfen, ohne die gebuchte Maschine schon nutzen zu dürfen.

Deine Zuordnungen prüfst du unter [Zugänge & Ressourcen](../benutzer/zutritt.mdx), [Meine Buchungen](../benutzer/buchungen.mdx) und [Meine Qualifikationen](../benutzer/kompetenzen.mdx).

## Was bewirkt eine Deaktivierung?

Eine Deaktivierung sperrt neue Anmeldungen und erhält das Konto mit seinen Zuordnungen. Sie ist keine Löschung und beendet bestehende Zugriffe nicht sofort. Vor einer Reaktivierung sollten die erhaltenen Rollen, Gruppen und Zutrittszuweisungen geprüft werden.

Die konkreten Schritte und Einschränkungen stehen unter [Konten deaktivieren und reaktivieren](../administration/benutzer-rollen.mdx#konten-deaktivieren-und-reaktivieren).

## Zuständigkeiten und persönliche Nutzung

Objektbezogene Verwaltungszuordnungen können die Zuständigkeit für bestimmte
Bereiche begrenzen. Eine persönliche Ressourcenfreigabe oder Einweisung genügt
allein nicht zum Verwalten dieses Bereichs oder zum Empfang seiner Betriebsalarme.

Die Benutzeransicht zeigt auch bei Verwaltungsrechten nur eigene Daten.
Den Einstieg erklärt [Erste Schritte](../benutzer/erste-schritte.mdx), persönliche
Kontoeinstellungen das [Profil](./profil.mdx). Bei einem Kartenverlust oder unbekannten Zugriff beachte die
[Fehlerhilfe](./fehlersuche.mdx), statt aus einem Kontostatus eine sofortige Sperre
aller anderen Zugangsarten abzuleiten.
