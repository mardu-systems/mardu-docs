Der MCP-Endpunkt bietet Mardu-Daten und Aktionen an, keine Dokumentationssuche.

## MCP-Client verbinden

Mardu bietet MCP über **Streamable HTTP** an. Du benötigst einen kompatiblen
Client, eine erreichbare HTTPS-Adresse des Mardu-Servers und eine von der
Administration [freigegebene MCP-Richtlinie](../administration/mcp-verwalten.mdx).
Die Tokenverwaltung benötigt Profil-Lese- und Änderungsrechte.

<Steps>

<Step>

### Persönlichen Zugang erstellen

1. Erstelle im Profil eine [persönliche MCP-Verbindung](../ueberblick/profil-mcp.mdx#verbindung-erstellen).
   Wähle für den folgenden Test nur **Eigene Benachrichtigungen ansehen**.
2. Kopiere **MCP-Route** und **Bearer-Token** aus der einmaligen Zugangsanzeige.
   Speichere den Token außerhalb des Repositories und gib ihn nicht in Logs aus.

</Step>

<Step>

### Client konfigurieren

1. Wähle im Client den Transport **Streamable HTTP**. Verwende die erreichbare
   Serveradresse mit der angezeigten Route, beispielsweise
   `https://mardu.example.invalid/mcp`. Ersetze die Beispieladresse und
   gegebenenfalls `/mcp` durch die Werte deiner Installation.
2. Hinterlege den Token im Authentifizierungsfeld des Clients. Verlangt der Client
   einen HTTP-Header, verwende `Authorization: Bearer <dein-token>`.

</Step>

<Step>

### Einen Leseaufruf prüfen

1. Initialisiere die Verbindung mit `initialize` und lade die Werkzeuge mit `tools/list`.
2. Rufe `notifications_list` mit `limit: 1` auf. Das Tool liest nur den
   Posteingang des Tokeninhabers; eine leere Liste ist eine gültige Antwort.

Falls der Client Tool-Aufrufe als JSON annimmt, lautet der Inhalt für `tools/call`:

```json
{
  "name": "notifications_list",
  "arguments": {
    "limit": 1
  }
}
```

Das Beispiel enthält die MCP-Aufrufparameter. Der Client übernimmt die
Protokollnachrichten und muss beim zustandslosen Transport den Bearer-Token mit
jeder HTTP-Anfrage senden, auch nach erfolgreicher Initialisierung.

`notifications_list` benötigt `Permissions.Profile.View`. Die Seitengröße muss
zwischen 1 und dem Serverlimit liegen; mit `afterCursor` kann der Client eine
weitere Seite anfordern.

</Step>

</Steps>

### Rechte und Tokenwechsel

Bei persönlichen Verbindungen begrenzen die delegierten Rechte, die aktuellen
Rechte des Kontos und die Serverrichtlinie jeden Tool-Aufruf gemeinsam.
Auch sichtbare Tools können für deinen Token gesperrt sein. Schreibende oder
destruktive Tools benötigen die entsprechende Serverfreigabe. Lade die
Werkzeugliste nach Rechte- oder Richtlinienänderungen neu. Die Serveranweisungen
verlangen für schreibende Aufrufe eine klare Nutzerabsicht, für destruktive
Aktionen eine ausdrückliche Bestätigung. Beachte die Bestätigungsparameter des Tools.

Zum [Erneuern oder Widerrufen](../ueberblick/profil-mcp.mdx#zugang-ersetzen-oder-widerrufen)
verwendest du das eigene Profil. Ersetze nach einer Erneuerung den Token im Client;
der alte ist sofort ungültig. Das Ablaufdatum bleibt bestehen. Nach Ablauf oder
Widerruf erstellst du eine neue Verbindung, ohne gesonderte Antragsfreigabe.

### Fehler beim MCP-Zugriff

| Antwort oder Fehler         | Prüfen                                                                                                                                                                                         |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HTTP 401                    | Token fehlt, ist ungültig, abgelaufen oder widerrufen. Prüfe auch, ob MCP und persönliche Verbindungen noch freigegeben sind.                                                                  |
| HTTP 403                    | Der Endpunkt kann deaktiviert sein oder ausschließlich Agent-Tokens verlangen. Prüfe die Serverrichtlinie. Fehlende Tool-Rechte können auch als Fehler innerhalb einer MCP-Antwort erscheinen. |
| HTTP 404                    | Prüfe Serveradresse, Proxy und konfigurierte MCP-Route.                                                                                                                                        |
| HTTP 429                    | Der Zugriff ist begrenzt. Reduziere parallele Aufrufe und warte vor dem nächsten Versuch; beachte einen gegebenenfalls gelieferten `Retry-After`-Header.                                       |
| `tool_disabled`             | Die aktuelle Serverrichtlinie sperrt diese Tool-Art. Lade die Werkzeugliste neu.                                                                                                               |
| `validation_error`          | Prüfe die Tool-Parameter, etwa Seitengröße und Pflichtangaben.                                                                                                                                 |
| `not_found` oder `conflict` | Lies den betroffenen Datensatz erneut und prüfe den aktuellen Zustand, bevor du eine Änderung wiederholst.                                                                                     |

Prüfe HTTP-Status und MCP-Tool-Fehler im Client; protokolliere keine Zugangsdaten.
