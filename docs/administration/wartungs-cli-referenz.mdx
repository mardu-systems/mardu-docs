Die Aufrufe gelten für `mardu-admin` im laufenden API-Container.
Voraussetzungen, Menü und Passwortwiederherstellung erklärt die
[Anleitung zur Wartungs-CLI](./wartungs-cli.mdx). Die CLI verwendet Englisch.

## Aufruf und Hilfe

Alle Beispiele werden auf dem Server im Installationsordner ausgeführt. Der
vollständige Aufruf lautet:

```text
docker compose exec --user mardu server /app/maintenance/mardu-admin BEREICH BEFEHL [OPTIONEN]
```

Ohne Bereich und Befehl öffnet sich das Menü. Die Hilfe funktioniert ohne
Verbindung zum Wartungslistener. Für die Hilfe zu einem einzelnen Befehl hängst
du `--help` an diesen Befehl an:

```bash
docker compose exec --user mardu server /app/maintenance/mardu-admin --help
docker compose exec --user mardu server /app/maintenance/mardu-admin user reset-password --help
```

`mardu-admin` ist die CLI für Kontowiederherstellung und Serverdiagnose. Die
separate Geräte- und Signatur-CLI `mardu-management` hat andere Befehle.

| Option            | Verfügbar bei                                  | Bedeutung und Standard                                                                              |
| ----------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `--help`          | Hauptaufruf, Bereiche und einzelne Befehle     | Zeigt die jeweilige Hilfe.                                                                          |
| `--email <EMAIL>` | Allen `user`-Befehlen und `session revoke`     | Erforderliche E-Mail-Adresse des Zielkontos; ohne Standardwert.                                     |
| `--permanent`     | `user reset-password`                          | Verlangt nach dem Reset keinen Passwortwechsel. Ohne diese Option ist der Reset temporär.           |
| `--json`          | `user show`, `system doctor`, `system version` | Gibt erfolgreiche Ergebnisse als JSON aus. Ohne diese Option verwendet die CLI Tabellen und Panels. |

## Konten und Anmeldesitzungen

Die folgende Tabelle zeigt den Teil des Aufrufs hinter
`/app/maintenance/mardu-admin`. Ersetze `admin@example.com` durch die
E-Mail-Adresse des Zielkontos.

| Befehl                                                      | Wirkung                                                                                                                                                                                 |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `user show --email admin@example.com`                       | Zeigt ID, E-Mail-Adresse, Benutzername, Aktivierung, E-Mail-Bestätigung, zeitliche Kontosperre, MFA-Status, Passwortwechselpflicht und Unterstützung lokaler Passwortwiederherstellung. |
| `user reset-password --email admin@example.com`             | Setzt ein temporäres Passwort, verlangt einen Wechsel beim nächsten Login und widerruft bestehende Anmeldesitzungen.                                                                    |
| `user reset-password --email admin@example.com --permanent` | Setzt das eingegebene Passwort dauerhaft und widerruft bestehende Anmeldesitzungen.                                                                                                     |
| `user unlock --email admin@example.com`                     | Setzt Fehlversuchszähler und zeitliche Kontosperre zurück.                                                                                                                              |
| `session revoke --email admin@example.com`                  | Widerruft die Anmeldesitzungen des Kontos, ohne dessen Passwort zu ändern.                                                                                                              |

`--email` muss eine gültige, nicht leere E-Mail-Adresse enthalten. Äußere
Leerzeichen werden bei der Prüfung und Kontosuche entfernt. Änderungen verlangen ein
interaktives Terminal und die Bestätigung des angezeigten Zielkontos. Die beiden
Reset-Varianten fragen das neue Passwort zweimal verdeckt ab. Es gibt keinen
Parameter zur Passwortübergabe und keinen Modus für Änderungen ohne Bestätigung.

Beispiel zum Aufheben einer zeitlichen Kontosperre:

```bash
docker compose exec --user mardu server /app/maintenance/mardu-admin \
  user unlock --email admin@example.com
```

Beispiel zum Widerrufen aller Anmeldesitzungen:

```bash
docker compose exec --user mardu server /app/maintenance/mardu-admin \
  session revoke --email admin@example.com
```

Aktivierung, E-Mail-Bestätigung und MFA-Vorgaben werden durch diese Aktionen nicht
geändert. Extern verwaltete Konten und Konten ohne lokales Passwort unterstützen
keinen lokalen Passwort-Reset.

## Diagnose und JSON-Ausgabe

| Befehl           | Ergebnis                                                                    |
| ---------------- | --------------------------------------------------------------------------- |
| `system doctor`  | Gesamtzustand und Ergebnisse der im Server registrierten Zustandsprüfungen. |
| `system version` | CLI-Version, Serverversion und Version des Wartungsprotokolls.              |

Die lesenden Befehle benötigen einen erreichbaren Wartungslistener, aber kein
interaktives Terminal. Mit `-T` schaltest du die Terminalzuweisung aus:

```bash
docker compose exec -T --user mardu server /app/maintenance/mardu-admin system doctor --json
```

`--json` liefert erfolgreiche Ergebnisse ohne Panels, Tabellen, Farben oder
Statusanimationen. Fehler erscheinen weiterhin als Text in einem Fehlerpanel.
Prüfe vor dem Einlesen den Rückgabewert.

Die Diagnose-JSON-Ausgabe enthält `status` und `checks`: den Gesamtzustand sowie
Prüfnamen mit den Zuständen `Healthy`, `Degraded` oder `Unhealthy`.
Die Versionsausgabe enthält `cliVersion` und `server` mit `version` und
`protocolVersion` (derzeit `1`). `user show --json` enthält folgende Felder:

| Feld                 | Typ                | Bedeutung                                                                                           |
| -------------------- | ------------------ | --------------------------------------------------------------------------------------------------- |
| `userId`             | String             | ID des Kontos.                                                                                      |
| `email`              | String oder `null` | E-Mail-Adresse des Kontos.                                                                          |
| `userName`           | String oder `null` | Benutzername.                                                                                       |
| `isActive`           | Boolean            | Das Konto ist aktiviert.                                                                            |
| `emailConfirmed`     | Boolean            | Die E-Mail-Adresse ist bestätigt.                                                                   |
| `isLockedOut`        | Boolean            | Eine zeitliche Kontosperre gilt.                                                                    |
| `mustChangePassword` | Boolean            | Nach der nächsten Passwortanmeldung ist ein Passwortwechsel erforderlich.                           |
| `twoFactorEnabled`   | Boolean            | Die Zwei-Faktor-Anmeldung ist aktiviert.                                                            |
| `hasLocalPassword`   | Boolean            | Ein lokaler Wartungs-Reset wird unterstützt; entspricht **Local password recovery** in der Tabelle. |

Passwort-Hashes, Tokens und MFA-Geheimnisse werden nicht ausgegeben.

Bei `Degraded` oder `Unhealthy` liefert `system doctor --json` die Diagnose
weiterhin als JSON, aber den Rückgabewert `1`.

## Rückgabewerte

| Wert  | Bedeutung                                                                                                                               |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `0`   | Befehl erfolgreich; bei `system doctor` sind die eingerichteten Zustandsprüfungen `Healthy`. Auch das Beenden des Menüs liefert `0`.    |
| `1`   | Aktion fehlgeschlagen, Kontoänderung ohne interaktives Terminal aufgerufen oder Diagnose meldet `Degraded` beziehungsweise `Unhealthy`. |
| `2`   | Ungültiger Aufruf oder Menüstart ohne interaktives Terminal.                                                                            |
| `69`  | Lokaler Wartungszugriff nicht erreichbar.                                                                                               |
| `130` | Bestätigung abgelehnt oder Ausführung abgebrochen. Nach bereits gesendeter Anfrage den Kontostatus prüfen.                              |

`1` umfasst auch ein nicht gefundenes Konto, abgelehnte Passwörter,
abweichende Wartungsprotokolle sowie ungültige oder leere Serverantworten.
Der Client wartet pro Anfrage höchstens 30 Sekunden. Auch das Überschreiten
dieser Wartezeit wird als Abbruch mit `130` gemeldet.

## Verbindung und Konfiguration

Der Wartungszugriff verwendet einen Unix-Socket: eine lokale Verbindung über
einen Dateipfad innerhalb des Containers. Es wird kein zusätzlicher Netzwerkport
veröffentlicht. Standardpfad im API-Container:

```text
/app/Private/Maintenance/control.sock
```

| Einstellung der API            | Standard                                                         | Wirkung                                                                                                                                  |
| ------------------------------ | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `LocalMaintenance__Enabled`    | `true`                                                           | Aktiviert den Wartungslistener unter Linux und macOS im Normalbetrieb. `false` deaktiviert ihn. Änderungen benötigen einen API-Neustart. |
| `LocalMaintenance__SocketPath` | `Private/Maintenance/control.sock` unter dem Server-Content-Root | Optionaler absoluter Alternativpfad. API und CLI müssen denselben Pfad verwenden. Änderungen benötigen einen API-Neustart.               |

Im Docker-Betrieb sind keine Änderungen nötig. So übergibst du einen Socket-Pfad
für einen einzelnen CLI-Aufruf:

```bash
docker compose exec --user mardu \
  -e LocalMaintenance__SocketPath=/app/Private/Maintenance/control.sock \
  server /app/maintenance/mardu-admin system version
```

Das Beispiel verwendet den Standardpfad. Ersetze ihn nur durch den absoluten
Pfad, auf dem der laufende Server seinen Wartungslistener bereitstellt. Die
Umgebungsvariable im Aufruf verschiebt keinen Socket und ändert keine API-Einstellung.

Das Socket-Verzeichnis ist auf den Serverbenutzer beschränkt (`0700`), der Socket
selbst auf Lesen und Schreiben durch diesen Benutzer (`0600`). Verwende bei
abweichenden Pfaden ein eigenes Verzeichnis, dessen Rechte beim Start angepasst
werden dürfen. Hebe diese Beschränkungen nicht auf, um Zugriffsfehler zu umgehen;
führe die CLI als `mardu` aus.

Änderungen werden mit Zielkonto und Betreiberidentität `local-maintenance` protokolliert.
Diese kennzeichnet den Wartungszugriff, keine Mardu-Benutzeranmeldung.
Passwörter, Hashes und Reset-Tokens werden nicht als Audit-Werte gespeichert.
