---
title: MCP für Agenten freigeben
description: MCP aktivieren, Agentenzugänge begrenzen, eine Verbindung prüfen und den Zugriff abschalten.
---

Über das **Model Context Protocol (MCP)** können Agenten Daten aus Mardu lesen
und freigegebene Aktionen ausführen. Hier legst du die Serverrichtlinie fest.
Persönliche Zugänge erstellt und widerruft jede Person im
[eigenen Profil](../ueberblick/profil-mcp.mdx).

## Voraussetzungen und Rechte

Öffne **Administration → Integrationen → MCP & Agents**.
Du benötigst **Einstellungen anzeigen**, zum Speichern zusätzlich
**Einstellungen bearbeiten**. Der Menüeintrag **Integrationen** benötigt
**Integrationen anzeigen**. Für den Verbindungstest muss der Client den Server
erreichen können; das Testkonto braucht die Rechte für die gewählte Aktion.

## MCP mit persönlichem Lesezugang einrichten

1. Aktiviere **MCP-Endpunkt aktivieren** und **Persönliche MCP-Verbindungen erlauben**.
2. Aktiviere **Nur Agent-Token zulassen**, wenn ausschließlich persönliche
   MCP-Tokens verwendet werden sollen. Clients mit normalen Benutzer-Zugangstokens
   werden dann abgewiesen.
3. Lasse **Schreibende Tools erlauben** und **Destruktive Tools erlauben** ausgeschaltet.
4. Prüfe die [Grenzwerte](#grenzwerte-wählen) und wähle **Speichern**.
5. Erstelle mit dem Testkonto eine [persönliche Verbindung](../ueberblick/profil-mcp.mdx#verbindung-erstellen)
   mit der benötigten Leseberechtigung.
6. [Richte den Client ein und führe den Lesetest aus](../entwickeln/mcp-anbindung.mdx#mcp-client-verbinden).
   Prüfe, ob er eine erfolgreiche Antwort erhält.

Die Richtlinie gilt nach dem Speichern ohne Serverneustart.
**Verwerfen** setzt ungespeicherte Änderungen auf den geladenen Stand zurück.

## Grenzwerte wählen

| Feld                         | Bedeutung                                                                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Maximale Seitengröße         | 1–100 Einträge je Antwortseite.                                                                                                 |
| Verbindungen pro Benutzer    | 1–25 aktive persönliche Verbindungen. Eine kleinere Grenze widerruft bestehende Verbindungen nicht.                             |
| Maximale Gültigkeit in Tagen | 1–365 Tage für neue Verbindungen. Ohne kürzere persönliche Angabe gilt dieser Wert. Bestehende Ablaufdaten bleiben unverändert. |
| MCP-Route                    | Serverpfad, üblicherweise `/mcp`. Im Formular nur lesbar.                                                                       |

## Schreib- oder Löschzugriff erlauben

Mit **Schreibende Tools erlauben** gibst du das Erstellen und Ändern von Daten frei.
**Destruktive Tools erlauben** schaltet zusätzlich das endgültige Löschen von
Geräten frei und setzt den Schreibzugriff voraus.

1. Aktiviere die benötigte Tool-Art und wähle **Speichern**.
2. Lass die Person eine Verbindung mit den benötigten Berechtigungen erstellen.
   Bestehende Verbindungen erhalten keine zusätzlichen Rechte.
3. Lade im Client die Werkzeugliste neu und prüfe die Aktion mit Testdaten.

Serverrichtlinie, ausgewählte Tokenrechte und aktuelle Kontorechte müssen die
Aktion erlauben. Objektbezogene Zugriffsregeln gelten weiterhin.

## Zugriff einschränken oder abschalten

Abschalten widerruft keine Tokens. Nach erneuter Freigabe können noch gültige
Tokens wieder funktionieren. Für einen dauerhaften Entzug muss die Person die
[Verbindung zuerst im Profil widerrufen](../ueberblick/profil-mcp.mdx#verbindung-widerrufen).

1. Wähle die benötigte Einschränkung:
   - **Destruktive Tools erlauben** ausschalten: Löschen von Geräten sperren.
   - **Schreibende Tools erlauben** ausschalten: Schreib- und Löschaktionen sperren.
   - **Persönliche MCP-Verbindungen erlauben** ausschalten: persönliche Tokens und deren
     Verwaltung im Profil sperren. Andere zugelassene Benutzer-Tokens können
     den Endpunkt weiterhin nutzen.
   - **MCP-Endpunkt aktivieren** ausschalten: alle MCP-Anfragen sperren.
2. Wähle **Speichern**. Die Richtlinie wird bei folgenden Anfragen geprüft.
3. Prüfe im Client, dass die betroffene Aktion oder Verbindung abgewiesen wird.

## Probleme beheben

| Beobachtung                           | Nächster Schritt                                                                                                                |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Nur Lesezugriff oder gesperrtes Feld  | Prüfe Bearbeitungsrechte und Konfigurationsquelle. Vorgaben außerhalb des Dashboards muss die technische Administration ändern. |
| Speichern abgelehnt                   | Prüfe Feldfehler und Grenzwerte. Der Entwurf bleibt erhalten; prüfe nach erneutem Laden den gespeicherten Stand.                |
| MCP im Profil deaktiviert             | Endpunkt und persönliche Verbindungen müssen beide aktiviert sein.                                                              |
| Client-Verbindung abgewiesen          | Prüfe Adresse, Route, Tokenstatus und **Nur Agent-Token zulassen**.                                                             |
| Aktion abgewiesen                     | Prüfe Tokenrechte, Kontorechte und erlaubte Tool-Art. Lade die Werkzeugliste neu.                                               |
| Verbindung lässt sich nicht erstellen | Prüfe Laufzeit und Zahl aktiver Verbindungen. Widerrufe nicht mehr benötigte Zugänge im Profil.                                 |

Bei Ladefehlern lade die Seite erneut. Technische Client-Fehler sind unter
[MCP-Zugriff](../entwickeln/mcp-anbindung.mdx#fehler-beim-mcp-zugriff) beschrieben.
